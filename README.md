银行储蓄管理系统——项目全部功能清单

一、登录与开户功能
1. 储户登录
输入账号和密码进行登录。
系统会检查账号、密码是否为空，并验证账号和密码是否正确。
如果账户被冻结，则禁止登录并提示“该账户已被冻结，请联系管理员！”。
登录成功后进入用户业务管理界面。

2. 储户注册 / 开户
用户可以通过注册功能开设新的储蓄账户。
需要输入：
账号、姓名、密码、地址、储种。
储种包括：
定期1年：利率1.98%
定期3年：利率2.25%
定期5年：利率3.5%
系统根据选择的储种自动设置对应利率。
开户成功后，储户信息保存到 bank_data.json 文件中。

3. 管理员登录
通过主界面的“管理员登录”进入管理员登录功能。
输入正确的管理员密码后进入管理员管理界面。

二、用户端功能
4. 存款
用户输入存款金额。
系统检查存款金额是否合法以及账户是否可以进行业务操作。
存款成功后增加账户余额，并生成一条存款交易记录。

5. 取款
用户输入取款金额。
系统检查金额是否合法、账户是否挂失以及账户余额是否足够。
余额不足时取款失败。
取款成功后减少账户余额，并生成一条取款交易记录。

6. 转账
用户输入：
转入账号、转账金额、转账备注。
系统进行以下有效性检查：
（1）转入账号是否存在；
（2）是否给自己转账；
（3）转账金额是否大于0；
（4）单笔转账金额是否超过50000元；
（5）转出账户是否冻结；
（6）转出账户是否挂失；
（7）转入账户是否冻结；
（8）转入账户是否挂失；
（9）转出账户余额是否足够。
检查通过后：
转出账户余额减少；
转入账户余额增加；
双方分别生成一条转账交易记录；
最后保存数据。

7. 查询余额
用户可以查询当前登录账户的余额。
系统根据当前登录账号找到对应储户，并显示账户余额。

8. 查询交易记录
用户可以查看当前账户的交易记录。
显示内容包括：
交易编号、交易时间、交易类型、交易金额、对方账号、备注、营业员工号等。
目前可以查看：
存款、取款、转账、开户存款等交易记录。

9. 修改储户信息
用户可以修改自己的：
姓名、密码、地址。
修改完成后，系统保存修改后的数据。

10. 查看利息
系统根据：
账户余额、储种、利率和存款年限
计算预计利息。
显示：
账号、姓名、储种、本金、预计利息、本息合计。
计算基本公式：
预计利息 = 本金 × 利率 × 年数
本息合计 = 本金 + 预计利息

11. 账户挂失
用户可以对自己的账户进行挂失。
系统记录账户的挂失状态和挂失日期、时间。
账户挂失后不能正常进行存取款等业务。

12. 退出登录
用户点击“退出登录”后退出当前用户界面，并返回系统登录界面。
三、管理员端功能
13. 显示所有储户
管理员可以查看系统中的所有储户。
储户信息通过 QTableView 表格显示。
表格共有8列：
（1）帐号
（2）姓名
（3）地址
（4）储种
（5）余额
（6）账户状态
（7）挂失日期
（8）冻结日期

14. 按账号查询储户
管理员输入储户账号后，可以查询指定储户。
查询结果只显示对应储户的信息。

15. 按账号排序
管理员可以按照账号进行排序：
账号升序；
账号降序。

16. 按余额排序
管理员可以按照余额进行排序：
余额从高到低；
余额从低到高。

17. 按储种筛选
管理员可以按照储种筛选储户：
定期1年；
定期3年；
定期5年。

18. 按账户状态筛选
管理员可以按照账户状态进行筛选：
正常；
已挂失；
已冻结。

19. 修改储户信息
管理员可以修改指定储户的：
姓名、密码、地址、储种。

修改储种时，系统会同步设置对应利率。

20. 删除储户
管理员可以删除储户。
删除时若储户余额大于零则不能删除。

21. 查看储户交易记录
管理员输入指定储户账号后，可以查看该储户的交易记录。
显示：
交易编号、日期、交易类型、金额、营业员工号。

22. 查看储户利息
管理员可以查询指定储户的利息信息。
显示：
储户信息、储种、本金、预计利息、本息合计。

23. 管理员开户 / 添加储户
管理员可以直接添加新的储户。
需要输入：
账号、姓名、密码、地址、储种、初始余额。
系统根据储种自动设置利率。
添加成功后生成一条“开户存款”交易记录。

24. 冻结账户
管理员可以冻结指定储户账户。
冻结后：
账户状态变为“已冻结”；
系统记录冻结日期和时间；
被冻结的账户不能登录系统。

25. 解冻账户
管理员可以解除指定账户的冻结状态。
解冻后：
账户恢复正常状态；
冻结日期被清除；
储户可以重新登录系统。

26. 管理员退出登录
管理员点击“退出登录”后退出管理员界面，并返回系统登录界面。


四、数据持久化功能
27. 保存数据
系统使用 Qt 文件和 JSON 功能保存数据。
主要使用：
QFile
QJsonDocument
QJsonArray
QJsonObject

保存文件：
bank_data.json

保存的储户数据包括：
账号、姓名、密码、地址、储种、利率、余额、挂失状态、挂失时间、冻结状态、冻结时间。
保存的交易数据包括：
交易编号、交易时间、金额、交易类型、营业员工号、对方账号、备注。

28. 读取数据
程序启动时读取 bank_data.json 文件。
重新构造储户和交易记录。
因此：
关闭程序后重新打开，之前的数据仍然存在。

五、Qt / C++ 技术实现
29. 面向对象设计
项目主要使用以下类：
Customer
Transaction
BankSystem
CustomerTableModel
MainWindow
UserWindow
AdminWindow

30. Customer 类
Customer 是储户核心数据类。
主要保存：
账号；
姓名；
密码；
地址；
储种；
利率；
余额；
挂失状态；
挂失日期；
冻结状态；
冻结日期；
交易记录。
Customer 中使用：
QList<Transaction>保存一个储户的多条交易记录。

31. Transaction 类
Transaction 表示一笔具体的交易。
主要保存：
交易编号；
交易时间；
交易金额；
交易类型；
营业员工号；
对方账号；
备注。
交易类型包括：
存款；
取款；
转账；
开户存款等。

32. BankSystem 类
BankSystem 负责管理整个银行系统。
主要功能包括：
添加储户；
删除储户；
查找储户；
储户登录；
存款；
取款；
转账；
冻结账户；
解冻账户；
保存数据；
读取数据。
可以简单理解为：
BankSystem负责管理整个银行系统；
Customer负责表示一个储户；
Transaction负责表示一笔交易。

33. Customer 与 Transaction 的关系
一个 Customer 可以拥有多条 Transaction。


关系可以理解为：
BankSystem
    ↓
多个 Customer
    ↓
每个 Customer 拥有多个 Transaction

34. Model/View
管理员储户表格采用：
QTableView + CustomerTableModel + QList<Customer>
其中：
QTableView：负责显示表格。
CustomerTableModel：负责向 QTableView 提供储户数据和表头。
QList<Customer>：保存储户数据。
这种方式实现了数据和界面显示的分离。

35. 信号与槽
Qt 使用信号与槽机制处理按钮事件。
例如：
存款按钮
↓
clicked信号
↓
on_depositButton_clicked()
↓
BankSystem::deposit()
↓
更新余额和交易记录
↓
保存数据

36. Qt 文件操作与 JSON
项目使用 Qt 的 QFile 进行文件读写。
使用：
QJsonObject表示一个 JSON 对象；
QJsonArray表示 JSON 数组；
QJsonDocument表示整个 JSON 文档，并负责 JSON 数据和文本之间的转换。
最终数据保存到：bank_data.json
